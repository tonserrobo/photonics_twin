# SPEAR Photonics Digital Twin

Feasibility prototype (v0.1): Bragg grating simulator across C++ TMM core,
pybind11 bindings, FastAPI backend, and React UI with live WebSocket recompute.

## Quick start

```bash
# Python + C++ build (editable install)
uv venv && uv pip install -e .[dev]

# C++ unit tests
cmake -B build -S . && cmake --build build && ctest --test-dir build --output-on-failure

# Python tests (binding + API + WS)
uv run pytest

# Run the stack
uv run uvicorn photonics_twin_app.main:app --reload      # terminal 1
cd src/frontend && npm install && npm run dev            # terminal 2
# open http://localhost:5173
```

## Scope and limitations (v0.1)

This slice is a **single-component Bragg grating simulator and integration
prototype**, not an FPGA implementation or a calibrated digital twin.

It models a 1-D, normal-incidence, lossless Si/SiO2 quarter-wave stack with
Sellmeier dispersion, linear temperature dependence, and returns reflectance
only. It supports 2-16 periods (4-32 layers), 400-2500 nm design centres,
200-3000 nm sweeps, and -40 to 200 C.

It does not model angle or polarisation, absorption or gain, strain,
ambient-index response, fabrication tolerance, apodisation, waveguides/PICs, or
multi-component systems. FPGA acceleration is a design path under evaluation,
not a delivered capability. See `evaluation/scope_and_sme_alignment.md` for the
full assessment.

## Docker

Two images: backend compiles the C++ core into a wheel and discards the toolchain;
frontend builds the Vite bundle and serves it from nginx, which also proxies the API
and WebSocket so the UI is single-origin.

```powershell
.\run.ps1                        # build + start, wait for health, open the UI
.\run.ps1 -NoBuild               # start existing images
.\run.ps1 -Logs                  # follow logs
.\run.ps1 -Down                  # stop and remove the stack
```

The UI is at http://localhost:5173; the API is also exposed on http://localhost:8000.
The UI can export the spectrum as CSV or JSON and save/load a scenario.

For explicit image builds and the end-to-end smoke test:

```powershell
.\scripts\build.ps1              # both images, tagged from pyproject.toml + :latest
.\scripts\build.ps1 -Smoke       # ...then exercise the running stack
docker compose up                # UI + API on http://localhost:5173
```

`build.ps1` takes `-Service backend|frontend`, `-Tag <tag>` and `-NoCache`. Compose
reads `$TAG` (default `latest`), so `$env:TAG='0.1.0'; docker compose up` runs a
pinned build.

The backend reads material data from `$PHOTONICS_DATA_DIR` (set to `/app/data` in the
image). Leave it unset outside containers and it falls back to the repo tree.

## Evaluation

`evaluation/` holds reproducible research outputs for the v0.1 prototype:
simulator-vs-analytic validation, a period-count study, a throughput benchmark,
and the default reflectance sweep.

```powershell
.\.venv\Scripts\python.exe scripts\evaluate.py
```

The script checks the simulator against the independent Born & Wolf fixture
before writing, and aborts on a tolerance failure. See `evaluation/README.md`
for the metrics, output schema, and known limits.

`evaluation/scope_and_sme_alignment.md` assesses the simulation scope, the
FPGA readiness gap, and alignment with the SPEAR SME Needs Assessment. It also
lists the prioritised next steps. The current slice is a single-component
simulator and integration prototype, not an FPGA implementation or a calibrated
digital twin.

## Validation

The reference fixture at `data/validation/quarterwave_si_sio2_reference.json`
is generated by `scripts/compute_reference.py` from the closed-form
expressions in Born & Wolf §1.6.5 — an independent oracle for the simulator's
output. Re-run the script if material coefficients change.

The simulator's stop-band edges agree with the analytical oracle to
within ~1.3 nm; reflectance at the design wavelength matches to 1e-10.
